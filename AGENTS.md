# Contexto del proyecto

- El frontend usa HTML, CSS y JavaScript sin compilador ni dependencias de ejecución. Servir `frontend` por HTTP con el comando del README para compartir almacenamiento entre páginas.
- La apariencia compartida usa `frontend/js/theme.js` y la clave `nekopapata.appearance.v1`; conservar compatibilidad con los valores guardados. Cargar este script en el head, antes de los scripts específicos de cada página.
- `frontend/js/lector-data.js` expone `NekoReaderData.getChapter(storyId, number)`: promesa con metadatos de historia, capítulo, lista de capítulos, anterior/siguiente (número o null) y páginas con posición, URL, texto alternativo y dimensiones. Un capítulo inexistente devuelve null. Es el punto de sustitución por la futura API Go; no incluir credenciales Azure en el navegador.
- `frontend/biblioteca.html` comparte las vistas `general`, `continuar`, `favoritos`, `historial` y `listas` mediante `?vista=`. `NekoLibraryData.getLibrary()` devuelve historias, IDs de favoritos, historial ordenado por recencia y listas; son datos ficticios sin persistencia de actividad. La búsqueda (`q`), el género (`genero`, solo general) y la lista (`lista`, solo listas) se conservan en la URL. Las ilustraciones locales están en `biblioteca-portadas.svg`.
- Verificación rápida desde la raíz: `node --check frontend/js/app.js`, `node --check frontend/js/theme.js`, `node --check frontend/js/lector-data.js`, `node --check frontend/js/lector.js`, `node --check frontend/js/biblioteca-data.js`, `node --check frontend/js/biblioteca.js` y `git diff --check`.
- En bibliotecas, comprobar búsqueda por título/autor sin distinguir tildes, género combinado con búsqueda, selección de listas, URLs y restauración de filtros, estados vacíos y error/reintento, fichas y enlace al lector. Solo Entre estaciones tiene capítulos disponibles (11–13).
- Verificar en navegador: búsqueda y diálogo del menú; tema entre páginas, pestañas y navegación Atrás/Adelante; modo sistema; capítulos 11–13 y rutas inválidas; imágenes y reintento; almacenamiento bloqueado; anchos de 320 a 1440 px.
- `frontend/perfil.html` muestra el perfil propio; `?vista=publico` es solo una vista previa local sin controles de edición, no autenticación ni autorización. `NekoProfileData` (`perfil-data.js`) separa `getProfile`, `updateProfile`, `createPost` y `toggleLike` de la interfaz; almacena el perfil y hasta 100 publicaciones en `nekopapata.profile.v1`. La futura API debe comprobar identidad y propiedad en el servidor.
- El color del perfil usa `--profile-accent`/`--profile-on-accent`, independientemente del tema general. Fotos JPG/PNG/WebP de hasta 5 MB se recortan al centro y convierten a JPEG localmente (avatar 320×320, portada 1440×480); no se envían a Azure. Los errores de guardado deben conservar los formularios.
- Para cambios del perfil: `node --check frontend/js/perfil-data.js`, `node --check frontend/js/perfil.js` y `node --check frontend/js/app.js`. Probar edición/cancelación, las tres clases de publicación, reacción, enlace al lector, foto/portada, vista propia/visitante, tema independiente, sincronización con el menú, Atrás, almacenamiento inválido/bloqueado/lleno y móvil. El historial/favoritos de biblioteca sigue siendo ficticio e independiente del perfil local.
- `styles.css` referencia `assets/fonts/NextSunday.woff2`, ausente en el repositorio. El navegador usa la fuente alternativa; es una incidencia preexistente.
